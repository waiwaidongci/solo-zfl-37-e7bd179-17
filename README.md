# 试墨图像计量与复核台

由「墨锭试磨室」扩展而成的试墨纸照片采集、本地图像计量与复核留痕系统。零外部依赖，Node ≥ 18。

## 运行

```bash
npm start          # http://localhost:3037
npm test           # 端到端走查（自动起停服务、使用临时数据目录与随机端口）
```

数据保存在 `data/ink-station.json`（图片以 base64 与指标、版本、审计同库存放）。
旧版 `data/ink-stick-testing.json`（v1）首次启动时自动升级，并备份为
`data/ink-stick-testing.v1-backup.json`；旧墨锭台账在「档案」页仍可查看。

## 角色

页面右上角选择身份并填写姓名（写入审计）：

- **操作员（operator）**：建档、批量上传、标定；不能复核。
- **复核人（reviewer）**：只负责批准/驳回；不能参与任何采集。

**姓名与角色稳定绑定**：一个姓名首次发起写操作时，其角色会持久化到数据库；
之后同一姓名换角色请求一律返回 `403 identity_role_bound`（重启后仍生效），
因此无法用同一名字「先采集、再切复核人批准自己的版本」。
每个版本还单独记录采集参与者（`contributors`），服务端在复核时再拦截一次。
换人作业请使用不同姓名；分配角色应在第一次操作前确定。

## 采集与计量

1. 选择或新建留样，批量选择试墨纸照片（手机可直接调起相机）。
2. 在每张缩略图上拖动红色标线两端对齐纸面刻度，填写该标尺的已知毫米数；
   也可先填纸张 / 光照 / 水滴量默认值再一键套用整批。
3. 指标在浏览器本地即时预览，提交后以服务端同一份算法（`lib/imaging.js`）重新计量：
   - **扩散面积**：Otsu 阈值分割 → 最大连通域取墨团 → 按标定 `px/mm` 换算 mm²
   - **边缘清晰度**：墨团边界像素的 Sobel 梯度均值
   - **色阶分布**：墨团内 16 阶灰度直方图（另出模糊评分：拉普拉斯方差）
   - **重复检测**：8×8 平均哈希，汉明距离 ≤ 5 判重
4. 无效图会标注原因（`blurry` 模糊 / `duplicate` 重复 / `no_scale` 缺标定 /
   `no_ink` 未检出墨迹 / `decode_failed` 解码失败 / `missing_group` 缺归组信息），
   **单张失败不影响同批其余照片**。

同一留样按 **纸张 + 光照 + 水滴量** 归组；某组凑齐 **3 张有效图** 才自动生成结论
（组内面积均值与变异系数、清晰度、色阶分布等）并锁定版本、提交复核。
3 张有效图若分散在不同组（如 2+1），不出结论。

当前版本里因缺标定/模糊判无效的图，修正后允许重新提交同一张；
**历史冻结版本里的图片不得在新版本复用**（跨版本判重）。

## 复核与版本

- 待复核版本在「复核」页可看图、指标与结论；批准后版本冻结。
- 驳回必须填写原因：旧版本的图片、标定尺度、结论快照原样保留，
  系统另起一个 `collecting` 新版本供重新采集。
- 复核人若与采集为同一身份，服务端直接 403（职责分离在服务端强制）。

## 并发、幂等与一致性

- 所有写接口在进入指纹与写事务**之前**先做迭代式载荷校验（遍历本身使用显式栈，
  不随嵌套深度增长调用栈）：
  - 嵌套深度超过 64 层（根为 0，第 64 层值可接受）→ `400 json_depth_exceeded`，
    万级嵌套也稳定返回 400，不会栈溢出成 500；
  - 含非有限数字（超大指数如 `1e999` 解析成的 `Infinity`/`-Infinity`）→
    `400 non_finite_number`（响应带点分路径）。
  两类拒绝都不绑定身份、不写幂等记录、不写业务库。`-0`、下溢为 `0` 的极小指数、
  普通大整数、最大有限指数等均按正常 JSON 数值接受。
- 所有写接口接受 `Idempotency-Key`。载荷指纹先做 **TLV 规范化**（类型标签 + UTF-8
  字节长度前缀，无任何可打印分隔符）再做 SHA-256，因此：
  - 对象成员书写顺序无关（调换字段排列的同内容重试视为重放）；
  - 字符串内容里出现逗号、引号、等号、冒号、括号或类型标记字符也**无法伪造**
    出别的对象结构（长度前缀整体定界，解析端绝不在内容中扫描分隔符）；
  - 字符串与键按 **UTF-16 码元**逐码元定长编码：普通字符、中文、emoji 代理对
    原样保留，**孤立代理码元（lone surrogate，如 `\uD800` 与 `\uD801`）也各自不同**，
    不会像 UTF-8 那样塌成同一个替换字符 U+FFFD；
  - **保留数组顺序**（照片数组换序是不同请求，返回 409）；
  - **保留值类型**（`5` 与 `"5"`、`null` 与 `{}`、`true` 与 `1` 均不同）；
  - 图片 dataUrl 按完整字节参与，任何字节变化都返回 409。
- 幂等匹配按以下两类，与记录上是否同时存在其他摘要字段无关：
  1. **安全 TLV 指纹**：新记录（及任何带安全摘要的记录）支持字段换序重放，
     分隔符注入与孤立代理串均无法伪造等价内容；
  2. **原始 JSON 指纹精确相等**：任何历史记录都允许「同一请求原样重试」命中回放。
     即使一条记录三类指纹齐全，也不会因为带安全摘要字段而拒绝其原始请求。

  中间版本的「键序无关文本摘要」（`fingerprintCanonical`）**永不参与**任何
  字段换序或内容等价判断——它无法仅凭哈希证明内容相同（分隔符注入、孤立代理
  码元都会让不同对象得到相同摘要）。因此没有安全摘要的老记录：原样重放可命中，
  字段换序、分隔符注入、代理碰撞、真实业务变更均返回 409。
- 前端批量上传/复核自动生成幂等键，重复提交、双击、超时重试只成功一次。
- 全部写操作经单一互斥链串行化，**并发复核只有一次成功**，其余得到 409。
- 图片、指标、版本状态、审计在同一 JSON 事务内提交：
  先写临时文件再 `rename` 原子落盘；落盘失败立即回滚内存快照，
  不会出现图片存了但指标/审计没存的部分保存。
- 审计页可查建档、批量采集、批准、驳回、v1 迁移等全部动作及操作人。

## 手机适配

视口按手机布局适配：标签页吸顶、缩略图标定支持触摸拖动、表单与卡片单列排布。

## 目录

```
server.js            HTTP API + 静态托管
lib/imaging.js       图像计量纯函数（浏览器与 Node 共用）
lib/png.js           最小 PNG 编解码（服务端权威解析/测试造图）
lib/store.js         事务化存储、v1 迁移、互斥与原子写
public/              单页前端（采集/复核/档案/审计）
test/                端到端走查与合成试墨纸图片
data/                JSON 数据与 v1 备份
```

### 测试用故障注入

走查需要模拟写盘失败，仅当设置环境变量 `ALLOW_FAULTS=1` 时开启
`POST /api/testing/fail-next-write`（使下一次落盘失败），生产环境不要开启。
